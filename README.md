# GLM 月预算保护（AstrBot 提供商插件）

**一句话**：在 AstrBot 原生智谱适配器外面套一层「每月 50 元」的预算账本——每次付费请求先预留额度，拿到厂商返回的用量后再结算；聊天和后台任务共享同一本账，预算不够就直接拒绝新的付费请求。

> 本插件不是智谱官方项目。它是给**自己的** AstrBot 实例做费用保护用的工程封装：账本按公开单价做保守估算，**不是厂商账单接口**，不能替代智谱后台的真实账单。

---

## 1. 功能特性

- **注册新的提供商类型**：插件加载后，「服务提供商」页面会出现类型 `dafeiyu_budgeted_zhipu`（显示名 `GLM 月预算通道（50元/月）`）。它继承 AstrBot 原生智谱适配器，调用方式和原生智谱提供商一致。
- **只允许已核价的模型**：请求里的模型必须是 `glm-5.3-flashx`，其他模型直接拒绝——账本只按这一个模型的价格记账，避免"未知价格"漏记。
- **只核价文本和图片**：音频、视频、文件，以及不是 `image_url` 的图片块，会直接拒绝。这些内容不会按“文本有多少字节”蒙混进预留。
- **只允许官方按量入口**：`api_base` 去掉末尾斜杠后必须等于 `https://open.bigmodel.cn/api/paas/v4`，否则提供商加载失败。这样避免把请求指向未核价的第三方中转。
- **先预留、后结算**：每次请求进入模型前，先在 SQLite 事务里预留一个保守上界；拿到厂商 `usage` 后才把预留改成真实费用。并发请求不会同时花超预算。
- **失败也保守记账**：报错、取消、拿不到权威用量，或者用量读数全是 0 的请求，预留额度**不会退回**——没有权威用量就不假装知道真实花费。用量字段存在但无法解析（负数、类型不对、大到无法入账）时，预留保留并冻结当月。插件也不自动重试，避免重复扣费。
- **超预留冻结当月**：如果厂商返回的用量比预留还高（价格变化、异常用量），账本会记录真实用量并冻结当月剩余额度，避免悄悄少记。
- **聊天与后台任务共享额度**：主聊天、记忆总结、日记、日程、说说草稿等，只要都指向同一个预算提供商，就共用一本账。
- **北京时间自然月**：按 UTC+8 的日历月结算，跨月自动换新月份，不需要手动重置。
- **流式降级为单次请求**：流式调用也会变成一次非流式请求，只保留一次计费，不额外起第二次运行。
- **不读工具**：工具调用一律拒绝，避免自动工具循环产生不可控费用。

## 2. 适用场景 / 不适用场景

### 适用

- 给某个付费模型（这里是智谱 `glm-5.3-flashx`）加一道每月固定预算的硬保护。
- 多个 AstrBot 插件/后台任务共用同一个付费 API，希望它们共享额度、都能看到同一本账。
- 想先小额试用，确认"超预算就拒绝"的行为符合预期，再决定是否长期使用。
- 接受"账本是保守估算、不是厂商账单"的工程折中。

### 不适用

- 需要按真实账单逐笔对账、开发票、多账号分摊的场景。
- 需要自动充值、自动提额、自动切换账号的场景。
- 需要工具调用、多步 Agent 编排的付费通道。
- 需要使用其他智谱模型或其他厂商模型的场景（本通道只核价 `glm-5.3-flashx`）。
- 需要逐 token 流式输出的场景（当前实现会合成一次请求）。

## 3. 工作原理

```
AstrBot 聊天 / 记忆总结 / 日记 / 定时任务
        │  text_chat(...)  (模型必须指向本预算提供商)
        ▼
BudgetedZhipu._query（本插件）
        │  1. 拒绝工具调用，拒绝空 Key
        │  2. bound_payload：校验模型，拒绝未核价的音视频和文件，压缩/限制图片和文本，计算保守预留
        │  3. ledger.reserve(预留金额)  ← SQLite BEGIN IMMEDIATE
        │     ├─ 本月已冻结，或已用 + 预留 > 50 元 → 拒绝本次请求
        │     └─ 否则插入一条 state=reserved 记录
        ▼
AstrBot 原生 ProviderZhipu._query（request_max_retries=1）
        │  4. 真正调用智谱官方按量 API
        ▼
response.usage + response.raw_completion.usage
        │  5. 同时读适配器 usage 和厂商原始 usage
        │     cost = 较高的输入 token×2 + 较高的输出 token×7（微元）
        │     输出取 completion 与 reasoning 的较高值，不把思考 token 再加一遍
        │  6. ledger.settle(令牌, cost)
        │     ├─ 正常：把 reserved 改成 settled，金额=真实费用
        │     ├─ 超过预留：记录真实用量、写 frozen 行，冻结当月
        │     ├─ 用量缺失或全是 0：不结算，预留保留
        │     └─ 用量无法解析：预留保留，并写 frozen 行
        ▼
返回响应给上层（用户看到回复；结算失败也会返回，预留保留。若已冻结，下一条付费请求会被拒绝）
```

### 账本状态

SQLite 表 `charges` 只有四个字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | TEXT 主键 | 预留/结算用的随机令牌；冻结行是 `freeze-年月`；历史种子行是调用方给的名字 |
| `month` | TEXT | 北京时间自然月，例如 `2026-11` |
| `amount` | INTEGER | 金额，单位**微元**（1 元 = 1,000,000 微元） |
| `state` | TEXT | 记录状态，见下表 |

| 状态 | 什么时候写入 | 是否计入当月已用 |
| --- | --- | --- |
| `reserved` | 请求发出前预留 | 是 |
| `settled` | 拿到权威 usage 后结算 | 是（按真实金额） |
| `overrun` | usage 超过预留，记录真实用量 | 是（按真实金额） |
| `frozen` | usage 超过预留，或用量无法解析时写入的冻结标记，金额等于 50 元 | 是（当月额度归零） |
| `prior_trial` | 由 `Ledger.seed()` 手工写入的历史试验费用（插件代码不会自动调用） | 是 |

当月已用 = 当月所有状态的 `amount` 之和。预留时若本月已有 `frozen` 行，或「当月已用 + 本次预留 > 50 元」，直接抛 `BudgetDenied("本月API预算已达50元保护线，请下月再用付费模型。")`，不会调用厂商 API。

### 计价规则（代码里的真实取值）

| 项目 | 代码取值 | 说明 |
| --- | --- | --- |
| 月预算上限 `LIMIT` | `50_000_000` 微元 | 即 50 元 |
| 输入单价 | 2 元 / 百万 token | 即 2 微元/token；**缓存命中的输入也按原价计**，偏保守 |
| 输出单价 | 7 元 / 百万 token | 即 7 微元/token |
| 单次输出上限 | 2048 token | 强制 `max_tokens=2048` |
| 文本上限 | 131072 字节 | 图片被占位后的请求 JSON（UTF-8）体积，超过就拒绝 |
| 图片数量 | 最多 4 张 | 多一张直接拒绝 |
| 单图预留 | 65536 输入 token 等值 | 每张图按 65536 输入 token 计入预留 |
| 固定预留开销 | 4096 token 等值 | 覆盖消息角色的固定开销 |
| 预留公式 | `(文本字节 + 图片数×65536 + 4096) × 2 + 2048 × 7` 微元 | 结算后一般会明显回落 |

**注意**：上述价格是作者按当时公开的智谱单价做的**保守工程估算**。厂商调价、计费规则变化、缓存价格不同都会让账本与真实账单出现偏差；账本只能保证"不会因为估算过低而悄悄超支"这个方向，不能保证金额精确。

### 预留与结算细节

1. **预留**：SQLite `BEGIN IMMEDIATE` 事务里读取当月总和，判断余量后插入 `reserved` 记录，返回随机令牌。全程用整数微元，不用浮点数做预算判断。
2. **结算**：只接受非负整数金额；记录必须存在且状态为 `reserved`，否则报"预算记录不匹配"。
3. **正常结算**：把预留金额改成真实费用，状态改为 `settled`。
4. **超过预留**：把该记录的真实用量写入并标记 `overrun`，同时插入一条 `frozen` 记录（金额=50 元，主键为 `freeze-年月`，`INSERT OR IGNORE` 保证每月只有一条）。当月总和因此达到或超过上限，后续请求被拒绝。插件会写一条错误日志，但本次回复仍会正常返回给用户。
5. **没有退款**：报错、取消、`usage` 缺失，或适配器用量和原始用量都是 0 时不做结算，预留保持 `reserved`。这是有意的保守策略——没有权威用量就不假装知道真实花费。
6. **两份用量取较高值**：适配器整理后的 `TokenUsage` 可能把读不懂的原始用量变成 0。结算时同时看厂商原始 `usage`（含字典形式），输入、输出各自取较高的一份。`reasoning_tokens` 只在高于 `completion_tokens` 时才抬高输出，避免把已经包含在 completion 里的思考 token 再加一次。
7. **结算失败仍返回回复**：用量已经产生、但账本写入失败时，用户仍能看到这次回复，预留继续留在账本里。

### 注册时固定的字段

以下字段由注册模板和 AstrBot 决定，不需要手填，也不能通过插件配置修改：

| 字段 | 值 | 说明 |

| `type` | `dafeiyu_budgeted_zhipu` | 适配器类型，决定走本插件 |

## 4. 安装

### 4.1 插件市场安装（推荐）

1. 打开 AstrBot 后台「插件」页面。
2. 如果本插件已在 AstrBot 插件市场上架，搜索 `astrbot_plugin_dafeiyu_budget` 或「GLM 月预算」。
3. 安装后重载插件。

### 4.2 后台上传 zip

1. 把本仓库目录压缩成 zip（压缩包根目录直接包含 `main.py`、`metadata.yaml`）。
2. 在「插件」页的安装入口上传压缩包（按钮名称以你的 AstrBot 版本为准）。
3. 安装完成后重载插件。

### 4.3 手动放 data/plugins

1. 把整个目录复制到 AstrBot 数据目录下的 `plugins/astrbot_plugin_dafeiyu_budget`。
2. 确认 `main.py`、`ledger.py`、`metadata.yaml`、`requirements.txt` 都在目录根。
3. 重启或重载 AstrBot。

### 4.4 安装依赖

在 **AstrBot 实际运行的 Python 环境** 里执行：

```bash
pip install -r requirements.txt
```

`requirements.txt` 只有一行：`Pillow>=9.0.0`（图片压缩和尺寸校验用）。本插件还依赖 AstrBot 自带的智谱原生适配器 `astrbot.core.provider.sources.zhipu_source.ProviderZhipu`，不需要另外安装。

## 5. 配置项详解

本插件是**提供商适配器**，参数都在 AstrBot 的「服务提供商」页面配置，而不是「插件配置」页。`_conf_schema.json` 收录了同样的字段名和默认值，方便后台查看；插件读取的是提供商配置里的值。

| 配置项 | 类型 | 默认值 | 作用 | 示例 | 注意事项 |
| --- | --- | --- | --- | --- | --- |
| `id` | 字符串 | `glm_budget` | 提供商源 ID，AstrBot 用「提供商ID/模型ID」引用 | `glm_budget` | 已建提供商不会被自动改名；改 ID 要同步改上层引用 |
| `enable` | 布尔 | `true` | 是否启用 | `true` | 关闭后不加载 |
| `key` | 列表/字符串 | `[]` | 智谱开放平台按量 API Key，取第一个 | `["你的-智谱-API-Key"]` | 不要填 Coding Plan / 会员账号；插件不内置 Key。空 Key 在加载提供商时就会拒绝，请求也不会先预留再失败。字符串会收成只有一个元素的列表 |
| `api_base` | 字符串 | `https://open.bigmodel.cn/api/paas/v4/` | 智谱官方 API 入口 | 同默认值 | 代码校验：去掉末尾 `/` 后必须等于 `https://open.bigmodel.cn/api/paas/v4`，否则提供商加载失败 |
| `model` | 字符串 | `glm-5.3-flashx` | 模型 ID | `glm-5.3-flashx` | 唯一允许值；其他模型请求会被直接拒绝 |
| `timeout` | 整数 | `45` | 单次请求超时秒数 | `45` | 失败不会自动重试；失败/取消时预留额度保留 |

代码还会强制写入以下请求参数，**覆盖**提供商配置里原有的 `custom_extra_body`：

```python
{"thinking": {"type": "enabled"}, "reasoning_effort": "low", "max_tokens": 2048}
```

也就是说：思考模式开启、低推理档、输出上限固定 2048 token。这些值不是用户可调配置项。

## 6. 使用方法

1. **新建提供商**：在「服务提供商」页面新增，类型选 `GLM 月预算通道（50元/月）`。ID 可用默认值 `glm_budget`。
2. **填 Key**：填智谱开放平台**按量计费** API 的 Key。建议先确认账号有 `glm-5.3-flashx` 的可用权限。
3. **确认入口**：`api_base` 保持官方默认值，不要改成中转或代理地址。
4. **确认模型**：模型必须是 `glm-5.3-flashx`。
5. **把所有付费调用指向它**：主聊天、记忆总结、日记、日程、说说草稿等所有想纳入保护的调用，都改成这个提供商的模型。没有指向它的请求不受账本约束，会走原来的通道。
6. **准备回退**：预算用尽后本通道会拒绝请求。请在 AstrBot 里给聊天/任务配置其他备用模型（例如自己的其他提供商），保证还能继续工作。
7. **验证**：用一次简短纯文本聊天确认能正常回复；再查账本文件确认出现了 `settled` 记录。AstrBot 的"测试模型"按钮也会真实调用并计费，验证时注意。

权限边界：

- 插件本身不监听 QQ 消息、不注册命令；预算只对「使用这个提供商类型」的调用生效。
- 任何人都不能通过聊天命令绕过预算；但 AstrBot 管理员在后台切到其他提供商时，那部分调用不会被本账本记录。

## 7. 数据与隐私

- **账本位置**：`StarTools.get_data_dir('astrbot_plugin_dafeiyu_budget')` 返回的插件数据目录下的 `monthly.sqlite3`，通常在 AstrBot 数据目录的 `plugin_data/astrbot_plugin_dafeiyu_budget/` 下（以实际运行环境为准）。
- **账本内容**：只有随机令牌、北京时间年月、整数微元金额、状态四种字段。**不保存** API Key、提示词、聊天记录、图片、响应内容。
- **API Key**：保存在 AstrBot 的提供商配置中，由 AstrBot 管理；插件不写日志、不回显。
- **日志**：只在超预留冻结时写一条错误日志（不含 Key 和聊天内容）。
- **外发**：插件只按 AstrBot 原生逻辑调用智谱官方 API；不向其他地址发送数据，不上传账本。
- **清理**：账本是本地 SQLite 文件。停止实例 → 备份后删除 `monthly.sqlite3` 即可清零（所有月份记录都会消失）。不要在运行中直接删文件。
- **只读查看**（示例，把路径换成本机实际路径）：

```bash
py -c "import sqlite3; db=sqlite3.connect(r'<插件数据目录>/monthly.sqlite3'); print(db.execute('select month,state,sum(amount) from charges group by month,state').fetchall()); print('总计微元', db.execute('select coalesce(sum(amount),0) from charges').fetchone()[0])"
```

金额除以 1,000,000 就是元。

## 9. 常见问题 FAQ

**Q1：装好后「服务提供商」页面没有 `GLM 月预算通道（50元/月）` 这个类型。**
A：先确认插件已加载成功（插件页状态、日志）。常见原因是 AstrBot 版本里没有 `zhipu_source.ProviderZhipu`，或插件目录层级不对（`main.py` 必须在插件目录根）。

**Q2：提示"仅允许智谱官方按量API入口"。**
A：提供商配置的 `api_base` 被改过了。代码会先去掉末尾斜杠，再要求等于 `https://open.bigmodel.cn/api/paas/v4`；请恢复默认值，不要使用第三方中转。

**Q3：提示"预算通道只允许已核价的FlashX模型"。**
A：请求模型的不是 `glm-5.3-flashx`。检查提供商配置的模型字段；本通道只按这一个模型核价，其他模型会被直接拒绝，不会偷偷计费。

**Q4：提示"本月API预算已达50元保护线，请下月再用付费模型"。**
A：当月账本总和已经达到 50 元上限。等北京时间下个月自动换月，或先切到备用模型。预留是保守上界，有时单看已结算金额不高，但账本里还有未结算的预留，也会占用额度。

**Q5：请求失败了，为什么预算还是被扣了？**
A：这是设计行为。报错、取消、厂商没返回用量，或返回的用量全是 0 时，插件拿不到权威用量，因此保留预留、不退款，避免"失败就当免费"导致超支。用量字段无法解析时还会冻结当月。若失败频繁，请排查网络/Key/模型权限，并考虑把调用方重试次数调低。

**Q6：账本金额和智谱后台账单对不上。**
A：账本是按公开单价做的保守估算，不是厂商账单：输入缓存价、厂商调价、计费精度都可能有差异。请以智谱后台账单为准；本插件只负责"不超过预算"这个方向。

**Q7：为什么失败不自动重试？**
A：避免同一笔请求被重复计费。原生智谱适配器可能有自己的修复/重试逻辑，本插件在 `_handle_api_error` 里直接抛出错误，并用 `request_max_retries=1` 限制原生重试。

**Q8：图片报"图片必须先由原生适配器解析为有限的本地图片"或"图片无法解析或尺寸过大"。**
A：本通道只接受 `data:image/...;base64,...` 形式的内联图片。远程 URL（`http(s)://`）会被拒绝；同时最多 4 张、单图像素积不超过 4000 万、data URL 不超过 2400 万字符。坏图、截断的 base64、解压炸弹会变成这条预算拒绝，而不是一长串解析异常。音频、视频和文件会另外报"预算通道只接受文本和已核价的图片"。请确认走的是 AstrBot 原生的图片解析流程。

**Q9：文本太长报"上下文超过付费通道的长度保护线，请新开会话"。**
A：图片占位后请求 JSON 超过 131072 字节（128 KiB）。请新开会话、精简上下文或减少图片，避免一次请求预留过大。

**Q10：开了流式为什么没有逐 token 输出？**
A：当前实现把流式调用合并成一次非流式请求，只保留一次计费。设计取舍是"失败不重发、计费只一次"，不追求逐字输出。

**Q11：想改每月额度或单价怎么办？**
A：`LIMIT = 50_000_000`（微元）在 `ledger.py`，单价系数 `×2`（输入）和 `×7`（输出）在 `main.py` 的结算处。修改代码后需要重载插件；不要在运行中直接改数据库来"扩额"，容易绕过保护。

**Q12：当月冻结后还能恢复吗？**
A：冻结标记绑定当月，当月经账本总和达到上限无法再预留；北京时间换到下个月后会自动恢复。不要手工删除 `frozen` 行来解冻——那会绕过保护，也破坏账本一致性。

**Q13：多个插件/任务是不是自动共享预算？**
A：不是自动的。只有把它们的模型都指向同一个预算提供商，才会共享同一本账；停在原生智谱或其他提供商的调用不经本账本。

**Q14：能不能用其他智谱模型，或者 Qwen、Claude？**
A：不能。本插件只对 `glm-5.3-flashx` 核价并放行，这是为了防止未知价格漏洞。其他模型请用原生提供商，并自行评估费用。

**Q15：账本放在哪？能看吗？**
A：见第 7 节，`monthly.sqlite3`；可以用 SQLite 只读查询。账本不保存 Key、提示词和图片，给朋友看也不含隐私，但仍建议自己保管。

## 10. 兼容性

- 只拦截类型为 `dafeiyu_budgeted_zhipu` 的提供商；原生智谱提供商、其他厂商提供商不受影响，两者可以并存。
- 依赖 AstrBot 内置的 `ProviderZhipu`，因此 AstrBot 大版本升级后要重新确认该类的 `_query` 签名和 `custom_extra_body` 行为是否变化，否则可能加载失败或行为不一致。
- 插件代码不引用任何平台适配器，QQ 和其他 AstrBot 平台都可以用；`metadata.yaml` 的 `support_platforms` 按市场模板填写。
- 与记忆、日记、日程等插件兼容，前提是它们把模型指向本提供商；它们自己的重试次数会放大失败时的预留占用。
- 与其他预算/限流插件并存时可能重复限制，建议只保留一层预算保护，避免额度互相"打架"。

### 关键符号

- `TYPE`：提供商类型 `dafeiyu_budgeted_zhipu`。
- `MODEL` / `MAX_OUTPUT`：只允许的模型、强制输出上限。
- `bound_payload(payload)`：校验模型、拒绝未核价的媒体、压缩图片、计算文本字节与保守预留。图片旁边多出来的字段也计入文本体积。
- `quote_usage(response)`：从适配器用量和厂商原始用量取较高的输入/输出，换算成微元；缺失或全 0 返回 `None`，无法解析返回 `'bad'`。
- `prepare_provider_config(provider_config)`：校验官方入口和 Key，并把字符串 Key 收成列表。
- `BudgetedZhipu`：继承原生 `ProviderZhipu`，在 `_query` 里先预留、调用后再结算。
- `Ledger`：SQLite 账本；`reserve` / `settle` / `seed` / `total`。
- `BudgetDenied`：预算或范围校验失败时抛出的异常（`RuntimeError` 子类）。
- `BudgetPlugin`：插件生命周期，加载/注销提供商。

### 改代码注意

- 预算判断只用整数微元，不要引入浮点数。
- 任何新增的厂商 API 入口或模型，必须先核价再放行，否则会绕开账本的价格假设。
- `bound_payload` 的文本/图片限制是"预留上界"的一部分，放宽限制要同步估算成本，否则预留可能不够。
- 不要给失败请求加自动退款；没有权威用量时退款会破坏保守策略。
- 超预留的冻结逻辑依赖 `frozen` 行金额等于 `LIMIT`，改上限时两处要同步。
- 插件终止/重载要能重复执行：注销适配器、关闭提供商。

### 已知未验证项

- 未在 Linux/macOS 上验证 AstrBot 原生智谱适配器的具体行为。
- 未与智谱后台真实账单逐笔对账；账本只保证保守方向。
- 未验证 `glm-5.3-flashx` 之外模型的价格变化；本通道只核价当前模型。
- AstrBot 大版本升级后 `ProviderZhipu` 私有接口可能变化，需要重新验证。
